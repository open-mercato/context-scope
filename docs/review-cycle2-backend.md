# Review: cycle 2 backend (`packages/cli`)

Scope reviewed: `src/index/{watch,entry,overview,reader,scan,writer,manifest,worker}.mjs`, `src/server/{app,sse,analysis,http}.mjs` + `routes/*`, `src/commands/*`, `src/capture/*`, `src/export/*`, `src/rules/{index,habits}.mjs` + H-01..H-06, `src/setup/{inventory,instructions,budget,config}.mjs`, `src/adapters/{claude,claude-tools,codex,codex-tools}.mjs`, `src/ir/finalize.mjs`, `src/ir/calibration.json`, tests under `test/`. Read against ADR-003, `docs/review-cycle1-backend.md`, `docs/format-claude-code.md`, and the Claude Code hooks reference (field names checked on 2026-09-02).

Findings marked **verified** were reproduced with a node probe over `test/fixtures/` or synthetic input (no real transcripts opened; numbers only, see Appendix A). Line numbers refer to the files as of this review. Severity: **bug** (wrong number / wrong link / wrong file / leak), **risk** (wrong under plausible real input, or security/robustness), **cleanup**.

Overall: cycle 2 lands the right shapes (population rule with realpath, manifest-only habits, a watcher with a real polling fallback, a capture hook whose whitelist is checked against the vendor reference, an exporter that refuses on absolute paths). The problems concentrate in five places: the session population is defined three different ways; thresholds edits never re-evaluate stored findings; `observed.loaded` is attached to the wrong file; the live pass re-runs full discovery every time; and the forecast's minutes and threshold are extrapolated past what was measured.

## Top 10

### 1. "N sessions" has three definitions for the same repo — bug, verified
The overview, the recurrence table/habits, and the `scan` header each count a different population, and all three are printed as "sessions" of one repo:
- `overview.scope.sessions` (`src/index/overview.mjs:312-318`): top-level entries in range, where "top-level" is judged against the **machine** (`isNestedChildOf`, line 167).
- `overview.totals.runs` (`overview.mjs:220-224`): entries in range not nested **within the repo population** (`isNestedChild`, line 165). A Codex child whose parent was launched elsewhere counts as a session here but not above.
- `analysis.repoRecurrence().sessionCount` (`src/server/analysis.mjs:122-125`), `computeHabits().sessions` (`analysis.mjs:136-137`), `evaluateHabitsDetailed(...).sessions` (`src/rules/habits.mjs:189-192,213`), `aggregateStats().sessionCount` → `inventory.sessionCount` (`overview.mjs:355-362`, `src/setup/inventory.mjs:114`): **every** matching entry, Codex children included, all time.
- `overview.vendors[].sessions` (`overview.mjs:323`): every entry of the vendor on the machine, children included, unscoped.
- `scan` prints `scope.sessions` in the header, `totals.runs` on the next line, `habits.sessions` in the Habits title, and a vendor breakdown counted from the (limit-capped) `overview.runs` rows (`src/index/scan.mjs:35-41,82-83,93,109`).

Probe: the standard fixture home (2 Claude + Codex parent + Codex child, all in the repo) gives `scope.sessions 3 · totals.runs 3 · repoEntries 4 · stats.sessionCount 4 · habits.sessions 4 · recurrence.sessionCount 4`; with the Codex parent in another repo and two children in this one: `scope.sessions 1 · totals.runs 3 · habits.sessions 3`. Consequences beyond the header: H-01/H-02 "in ≥ 3 sessions" is satisfied by one Codex parent with three children; H-04's "last 10 sessions" window is diluted by zero-compaction children; SETUP recurrence (`S-01/S-02/S-06` × session count) and the first-change leverage are inflated.

**Fix (one population):** add `repoSessions(entries, { repoRoot, projectKey, since })` to `reader.mjs` and use it everywhere: (a) non-error entries with a summary; (b) attributed by `entryMatchesRepo`, with a Codex child whose `cwd` is null inheriting its parent's attribution; (c) top-level = no `parentThreadId`, or the parent is absent from the **whole manifest** (never from the filtered list); children never count as sessions — their requests/compactions/habit lists fold into the parent (`totals.subagents += 1` as today). Route `scope.sessions`, `totals.runs`, `trends.sessions`, `recurrenceByRule`/`sessionCount`, the habits record list (merge child `fat/fullReads/agents` into the parent record or drop children), `aggregateStats.sessionCount`, `vendors[].sessions` and the `scan` breakdown through it. One test asserting the four numbers are equal on the fixture home and on the parent-elsewhere case.

### 2. `PUT /api/v1/thresholds` never re-evaluates stored session findings — bug
`analysis.saveThresholds` (`src/server/analysis.mjs:261-283`) validates, writes `~/.contextscope/thresholds.json` and calls `invalidateSetup()`; nothing schedules an index pass. Session findings are read from `findings.json` per run (`writer.mjs:368-372`, `analysis.mjs:169`) and are only re-evaluated when `ensure()` runs and sees `previous.thresholdsHash !== thresholdsHash` (`writer.mjs:172`) — i.e. on the next live change, a manual refresh, or the next launch. Setup findings (cache invalidated) and habit findings (thresholds applied at read time) do move, so the UI shows a half-applied edit; `packages/ui/src/store.ts:77` explicitly assumes "rules re-run server-side".
**Fix:** after the write, `index.ensure().then(invalidateSetup)` (the route context already has `index`; `kickIndex` in `app.mjs:54-57` does the right thing), and return `{ thresholds, reevaluating: true }` so the UI can wait for the `done` event; the manifest path (`thresholdsHash` + `rulesHash`, which also covers the user file, `rules/index.mjs:100-105`) then re-evaluates without re-parsing.

### 3. `observed.loaded` is attached to the wrong instruction file — bug, verified
`src/setup/instructions.mjs:93-100 wasObserved` accepts `entry.endsWith("/" + display)`. The repo root file displays as `CLAUDE.md`, so an `InstructionsLoaded` record for `~/.claude/CLAUDE.md` (loaded in every session) or a `nested_memory` label `packages/api/CLAUDE.md` (176 in the local corpus, format doc §6) marks the **root** `CLAUDE.md` as `observed.loaded`. Probe on `test/fixtures/repos/check-pass`: `["~/.claude/CLAUDE.md"] → CLAUDE.md=observed.loaded`, `["packages/api/CLAUDE.md"] → CLAUDE.md=observed.loaded`. `budget.mjs:27-38` then relabels the whole chain `observed.artifact`, and S-01's "exact loaded chain" is exact about the wrong thing. The only test (`capture.test.mjs:176`) checks the positive case.
**Fix:** compare exact display strings (`observed.has(display) || observed.has(abs)`) plus the `~/` form of `abs`; drop the suffix heuristic. Add the two negative cases above.

### 4. Every live re-parse runs full discovery and spawns a worker pool — risk (performance)
`ensure({ only })` still calls `discoverAll` (`src/index/writer.mjs:153-154`) because change detection is stat-based; that means, per debounced change, `readHead` of 64 KB for every Claude main file plus `readdir` of every subagents dir (`src/adapters/discover.mjs:119-147,165-183`) and `readFirstLine` (up to 4 MB) for every Codex rollout (`discover.mjs:192-201,222-235`), then `createPool` (`writer.mjs:192-194`) spawns a fresh worker thread that re-imports the adapters and rules, and `saveManifest` rewrites the manifest (`writer.mjs:264`). Cycle 1 measured the incremental pass at 0.16 s for 250 files; on 2,000 files that is ~1.3 s of discovery (128 MB read + utf8 decode) per event, on top of the 2 s debounce and the ~0.2 s parse, so "≈ 2.5 s" becomes ≈ 3.5-4 s and ~40 % of a core while a session writes every few seconds. The ADR §3 said `only` should "skip discovery".
**Fix:** in `only` mode, stat only the listed files (main + its `subagents/`), reuse `cwd/projectKey/parentThreadId` from the existing manifest entry (fall back to discovery for a file the manifest has never seen), keep one warm worker for live passes (or parse in-process when `only.length === 1`), and record the live pass in `manifest.lastLivePass` rather than overwriting `lastPass` (`writer.mjs:263`; today `scan` reports "1 changed" after any live event and `watch.test.mjs:105` pins that).

### 5. Forecast minutes and threshold are extrapolated past what was measured — bug, verified
- `src/ir/finalize.mjs:133-139`: `perMinute` is a least-squares slope over wall-clock time. With a 3-hour break inside the last 20 requests (a resumed session), a synthetic linear ramp gives `minutesLeft 273.5` where the no-gap series gives `9`. Use active time (cap gaps at `ACTIVE_GAP_MS`, as `activeTime` already does) or always derive minutes from the request cadence over the active span.
- `finalize.mjs:105-107` + `calibration.json:57`: `autoCompact.claude.share = 0.999` was measured on five events on the 1M window (`window: 1000000` is stored but never consulted), and is applied to every window: a 200k session gets a 199,800 threshold labelled `estimated.local`, i.e. "no headroom at all", while the ADR expected ≈ 0.95-0.97. Key the calibration by window (`autoCompact.claude["1000000"]` as the ADR wrote it), fall back to `FORECAST_DEFAULT_SHARE` for windows without ≥ 3 events, and carry `basisWindow` in the threshold.
- `finalize.mjs:72,100-103`: the run's own "auto" compactions set the threshold with `preTokens.provenance`; for Codex `trigger: "auto"` is the ≥ 0.75 × window heuristic (`codex.mjs:384,415`, cycle-1 #16) and `preTokens` is the previous request's total, so the forecast line shows a `derived.exact` badge on an inferred number. Label Codex thresholds `estimated.local` until an auto-compaction is actually observed.

### 6. `hooks install` backs up settings files into the repository tree — risk (privacy)
`src/capture/install.mjs:176-179,214-217` writes `<file>.bak-<ts>` next to the settings file. For `--scope project` that is `<repo>/.claude/settings.json.bak-…` (committed with the next `git add .`); for `--scope local` it is `<repo>/.claude/settings.local.json.bak-…`, which the usual `.claude/settings.local.json` ignore pattern does **not** cover, so a file that routinely holds `env` values and API keys gains an unignored copy. Backups also accumulate on every install/uninstall. **Fix:** write backups under `~/.contextscope/backups/<sha1(path)>-<ts>.json` (0600) and print that path; keep at most a few per file.

### 7. Export leak check is line-anchored and label hashes are unsalted — risk (privacy), verified
- `src/export/schema.mjs:27,94-95`: `ABSOLUTE_PATH` only matches at a line start. `findAbsolutePaths({ a: "Bash: cat /Users/me/secret/keys.txt", c: "read /Volumes/client/acme/plan.md whole" })` returns nothing; only `"/Users/me/x/y"` is caught. Labels and finding prose that embed a path (a shell label, an S-05 broken-ref message, a `fix.summary`) therefore pass the gate. Match `(^|[\s"'`(=:,])` before the path and test evidence labels explicitly.
- `src/export/redact.mjs:15-17`: `h:` + 10 hex of an unsalted sha1 is a pseudonym, not a redaction: `package-lock.json`, `CLAUDE.md`, `src/index.ts` are recovered by a dictionary in milliseconds (probe: `h:fa288d1472`, `h:2d5d10cfc5`). Equality inside one export is the only property the ADR needs, so hash with a per-export random salt stored in `redaction.salt`. Also not rewritten: evidence labels of kinds `metric`/`request`/`run` (`redact.mjs:19,36-42`), `scope.agentType` (user-named agents), `block.tool.name`/`tool.server` (MCP server names) and `summary.models`.

### 8. H-06's fix is inverted — bug
`src/rules/H-06.mjs:7-12`: for `scope === "project"` (a `.mcp.json` server) it proposes `claude mcp remove <name>`, and for `user`/`local` scope it proposes `disabledMcpjsonServers` in `.claude/settings.local.json`. `disabledMcpjsonServers` only applies to `.mcp.json` (project) servers; user- and local-scope servers live in `~/.claude.json` and are removed with `claude mcp remove -s user|local <name>`. Every H-06 card therefore tells the reader to do the thing that does not work for that server. Swap the branches and keep the Codex `enabled = false` snippet.

### 9. `check` reads the developer's home config and exits 1 on runtime errors — risk / bug
- `src/commands/check.mjs:152-165` builds the inventory with `home`, so `src/setup/instructions.mjs:68-79` includes `~/.claude/CLAUDE.md`/`~/.codex/AGENTS.md` in the chain and budget, `src/setup/config.mjs:131-169` reads `~/.claude/settings.json`, `~/.claude.json` and `~/.codex/config.toml` (user hooks, user MCP servers), and `inventory.mjs:62-68 detectVendors` adds `claude` whenever `~/.claude` exists. The same repo then passes on CI (empty home) and fails on a laptop (a fat user-level CLAUDE.md, a user-scope MCP server, S-12 for a vendor the repo does not configure), or the reverse. The README promises "reads no sessions, no index and nothing under `~/.contextscope`" but not "nothing under `~`". Run `check` with `home` pointed at an empty directory (or a `--home none` mode in `buildSetupInventory`) and say so in the README.
- `check.mjs:242-248` maps only `CheckUsageError` to exit 2; any other error (EACCES on a file, a thrown rule) falls through to `src/contextscope.mjs:23-26` and exits **1**, which CI reads as "violations". Catch everything in `check.run` → exit 2 with the message.
- `check.mjs:215-218`: annotation `file=` values are not escaped for `,` and `:` (GitHub workflow-command property escaping); a path with a comma breaks the annotation.

### 10. Watcher debounce is trailing-only — risk (live mode starves under bursts)
`src/index/watch.mjs:272-280`: every event clears and re-arms the 2 s timer with no maximum wait. A Claude session in a tool loop writes a record every 0.5-1.5 s (tool_use, tool_result, attachment, `turn_duration`), so the re-parse fires only when the burst ends; during the phase where the forecast matters most, the UI sees nothing for minutes, and the ADR's "live ≤ 3 s after append" holds only for a single append (which is what `watch.test.mjs:73` tests). Add a max-wait (e.g. 5 s) alongside the debounce. Same file: `idleMs` is 3 min against the ADR's 120 s (`watch.mjs:42`), the watcher starts scanning `~/.claude/projects` before consent (`src/server/app.mjs:52`, `watch.mjs:347`; stat only, but before the page that says what will be read), and `runByFile` is written and never read (`watch.mjs:192,300,311`).

## 11-40

### Correctness

11. **Capture attribution needs `cwd === repo`, the population rule accepts descendants** — risk. `src/setup/inventory.mjs:52-60` keeps only records whose `cwdKey` equals `projectKeyFor(repoRoot)`; a session started in `packages/cli` or a `.claude/worktrees/*` checkout (attributed to the repo by `entryMatchesRepo`) never marks a file `observed.loaded`, and its `record.file` is `../../CLAUDE.md`-style (the capture script's `relative(cwd, …)` result keeps `..` on the absolute branch, `template.mjs:90`). Store `cwd`'s ancestors' keys, or have the hook record the git root's key next to `cwdKey`.
12. **H-01's Σ-tokens threshold is vacuous and Claude Bash results form one bucket** — risk. `src/rules/H-01.mjs:30`: `3 × repeatedFatResultTokens = 9,000`, but every entry of `habits.fat` is already ≥ `fatToolResultTokens` (8,000; `entry.mjs:342,376`), so three sessions always pass. `entry.mjs:377-378` keys by `(tool.name, label)` where the Claude adapter labels a Bash result with the tool name when there is no path target (`claude.mjs:494`), so all fat Bash outputs of a repo collapse into "Bash (shell)" while Codex results carry `cat path`. Use `classifyCommand` (already imported for `partial`, `claude-tools.mjs:73`) to give Claude Bash calls a target too, and make the Σ threshold mean something (e.g. Σ ≥ 3 × `fatToolResultTokens`).
13. **H-03 flags tiny handoffs and proposes files for built-in agents** — risk. `src/rules/H-03.mjs:38`: the `ratioP50 < 3` branch fires with no size floor (a 1.5k handoff from a 3k-peak agent is "fat"); `H-03.mjs:40` proposes `.claude/agents/Explore.md` for built-in types (`Explore`, `Plan`, `general-purpose`), which do not have a definition file. Require `handoffP50 ≥ fatHandoffTokens / 2` for the ratio branch and route built-ins to `CLAUDE.md`.
14. **Codex child rollouts distort H-04 and H-06 populations** — bug (part of #1). `H-04.mjs:22-26` windows over every record; `H-06.mjs:30-31` counts `records.length` per vendor. Both should see top-level sessions only (see #1).
15. **`joinCapture` runs after `finalizeRun`, not before** — cleanup. `src/index/worker.mjs:112-121` joins after `adapter.parse`, which already called `finalizeRun` (`claude.mjs:227`, `codex.mjs:749`). `launchedAt`/`deliveredAt`/`status` filled from `SubagentStart/Stop` (`join.mjs:88-94`) never reach handoff ratios or the summary, and `compaction.trigger` fixed by `PostCompact` is not seen by `forecastScope`'s auto-compaction filter. Either pass the records into `parse` (the adapter can call `joinCapture` before `finalizeRun`) or re-run `finalizeRun` when the join changed anything.
16. **`HABITS_VERSION` is stored but never compared** — cleanup. `entry.mjs:13,398` writes `habits.v`; `writer.mjs:166-175` re-tasks on adapter/estimator/calibration/thresholds/rules hashes only, so a change to `habitsOf` leaves stale records until a file's size/mtime moves. Add `previous.habits?.v !== HABITS_VERSION` to the `reevaluate` condition.
17. **`rulesHash` covers `H-*.mjs` and `habits.mjs`, which are evaluated at read time** — cleanup/perf. `rules/index.mjs:25`: editing a habit rule flags every stored run `rulesChanged` and re-reads every scope file of the index (`worker.mjs:103-109`) for nothing. Hash `[SB]-NN.mjs`, `util.mjs` and the thresholds files only; habit rules need no invalidation.
18. **`cwdReversible` is never computed for Claude entries** — cleanup. `entry.mjs:418-422` reads `candidate.cwdReversible`, which discovery never sets (`discover.mjs:146-160`), so a cwd-less file under a reversible project dir is attributed by rule 3 (`reader.mjs:149`) and simultaneously counted `unattributed` for every other repo (`reader.mjs:163`). Derive it from `projectDirName` in discovery; also `reader.mjs:133-134,142` documents an `entry.cwdReal` that nothing writes (the realpath cache does the work).
19. **`scan` counts from the row-capped list** — bug (minor). `scan.mjs:35-41` (vendor breakdown) and `scan.mjs:90` ("sessions above 80 %") iterate `overview.runs`, capped at `limit` (200); a repo with 1,234 sessions prints "Sessions 1,234 (claude 200)". Compute both in `buildOverviewFromEntries` from `recent`.
20. **Compaction threshold from every scope's auto compactions** — cleanup. `finalize.mjs:72` pools subagent compactions into `main`'s threshold and vice versa; per-scope thresholds are what the tail serves.
21. **`args.option` takes the next flag as a value; `hooks` picks the wrong word as its subcommand** — cleanup. `src/commands/args.mjs:17-20`: `contextscope check --repo --json` resolves the repo to `./--json`. `src/commands/hooks.mjs:22`: `hooks --scope project install` reads `project` as the subcommand and fails. Reject values starting with `-` and take the subcommand as `argv[0]`.

### Security / server

27. **Export route builds the `content-disposition` filename from decoded URL params** — cleanup. `src/server/routes/export.mjs:30-35`: `params.vendor` and `params.id` are percent-decoded (`routes/index.mjs:63`) and interpolated inside quotes; a `"` or CR/LF makes `writeHead` throw (caught, 500) rather than inject, but a `;` or `"` yields a malformed header. Whitelist `[A-Za-z0-9._-]` and, since `fetch()` cannot trigger a browser download, add `?download=1` support only if the UI needs it.
28. **`HEAD` requests 404** — cleanup. `routes/index.mjs:53-55` matches on `route.method === method`; `sendPrepared` handles HEAD but is never reached.
29. **`hooks install` replaces a non-array `hooks[event]` and reformats the file** — cleanup. `install.mjs:80-84` silently drops an invalid (object-valued) event entry; `install.mjs:170-174` re-serialises the whole file (indent detected, key order and inline arrays not preserved), so "existing groups byte-for-byte" holds only for `JSON.stringify`-shaped files. Refuse to touch a non-array event; say "reformatted" in the diff banner.
30. **The hook command depends on `node` being on Claude Code's PATH** — risk. `template.mjs:155`: under an nvm/asdf shell or a GUI launch, `node` resolves to nothing, `|| true` swallows it and the hook is a silent no-op; `hooks status` shows `0 record(s)` with no explanation. Install with `process.execPath` quoted (and re-check it in `hooks status`, offering to reinstall when it moved), or at least detect "sessions since install > 3 and 0 records" and say so. `sh -c` also means no Windows support; say so in the README.
31. **Watcher: symlinks and roots** — ok. `discoverWatchSet` uses dirent types (symlinked dirs/files are skipped), `watchDir` refuses paths outside the resolved roots, `mainFileFor` re-validates on every event (`watch.mjs:49-78,111-137,236-238`). No change needed; a test with a symlinked project dir would lock it in.
32. **Tail route input validation** — ok. `after` is integer-checked, `scope` resolves through `sha1(scopeId)` (no traversal), `sig` is compared as a string (`routes/runs.mjs:79-88`). Two notes: the UI sends `sig: ""` when `SubtleCrypto` is unavailable (`store.ts:192`) and the server then never reports `rebased`; and `buildTail` recomputes `requestsSignature` over up to `after` requests per call (fine at 1,500 requests, ~1 ms).

### Robustness / performance

33. **Tail and scope payloads re-read the 18 MB scope per live event** — risk. `routes/runs.mjs:84` reads `scopes/<id>.json` from disk on every tail call (no cache) and every `progress` event evicts the prepared shell/scope (`http.mjs:144-150`); the UI's full-scope refetch after a `rebased` tail re-serialises and gzips the scope (~1 s for the largest run). Cache the parsed scope object per `(runId, scopeId, entry.mtimeMs)` in the byte LRU and serve the tail from it.
34. **Exporter neither checks the importer's 50 MB cap nor bounds `--scopes all`** — risk. `schema.mjs:20` declares `MAX_EXPORT_BYTES` for the importer only; `--scopes all` on a 168-scope run clones every scope (`schema.mjs:70-76`), walks every string for paths (`findAbsolutePaths`) and, in redacted mode, scans every finding's prose against every label (`redact.mjs:50-64`, O(labels × findings)). Measure the serialised size before returning and refuse (or drop child scopes) above the cap with a clear message; sort labels once and use a single regex alternation.
35. **`reevaluate` re-reads every scope file of a run** — cleanup/perf. `worker.mjs:103-109`: a threshold or rule edit on 2,000 runs re-parses the full JSON of every scope (the 23 MB run included) to re-run rules that need requests and blocks. Fine for now; if rule edits become frequent, keep a per-scope digest the B-rules can run on.
36. **`getSetup` cache is not invalidated by live passes** — cleanup. `analysis.mjs:110-119`: live passes never call `invalidateSetup`, so `sessionStats` (hook runs, MCP invocations, `instructionFilesObserved`) lag up to 30 s behind `/habits` (which keys on `lastRunAt`). Key the setup cache on `lastRunAt` too.
37. **SSE sticky map and `liveRuns` are bounded by idle timers only** — ok/cleanup. `sse.mjs:85-91`, `watch.mjs:306-317`: one entry per live run, cleared after `idleMs`; `stop()` clears timers but not `liveRuns` (harmless, the accessor is removed). Fine; note the sticky replay sends every live run to each new subscriber, which is what the UI wants.
38. **Codex `cacheCreation` stays `undefined`** — cleanup (cycle-1 #15 stands). `codex.mjs:340,764-771` and the header say so on purpose; `types.ts` still declares a number. Set `0` when the field is absent and let the strip show "not reported" from a separate flag.

```js
// reader.mjs
export function repoSessions(entries, { repoRoot, projectKey, since } = {}) {
  const byRunId = new Map(entries.filter((e) => !e.error && e.summary).map((e) => [e.runId, e]));
  const parentOf = (e) => (e.parentThreadId ? byRunId.get(`${e.vendor}:${e.parentThreadId}`) : undefined);
  const attributed = (e) => entryMatchesRepo(e, { repoRoot, projectKey }) || (!e.cwd && parentOf(e) && entryMatchesRepo(parentOf(e), { repoRoot, projectKey }));
  const sessions = [];
  const children = new Map(); // parent runId -> child entries
  for (const e of byRunId.values()) {
    if (!attributed(e)) continue;
    if (since && entryTime(e) < since) continue;
    const parent = parentOf(e);
    if (parent) { (children.get(parent.runId) ?? children.set(parent.runId, []).get(parent.runId)).push(e); continue; }
    sessions.push(e);
  }
  return { sessions, children }; // callers fold children into their parent (requests, compactions, habits lists, subagents += 1)
}
```
