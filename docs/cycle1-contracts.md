# Cycle 1 implementation contracts

Shared interfaces between the parallel work streams. Every module must follow
these shapes exactly; `packages/cli/src/ir/types.ts` is the type authority and
`docs/adr-001-product-architecture.md` is the design authority. Format facts
come from `docs/format-claude-code.md` and `docs/format-codex.md`.

## Ground rules

- CLI stays plain ESM `.mjs`, Node >= 20, zero runtime dependencies.
- Privacy: no message text, tool output, prompt text, file contents, or absolute
  paths outside `~` may enter the IR, the index, the API, or the UI. Blocks carry
  sizes, hashes, tool names, attachment types, and repo-relative labels only.
- Every number the UI shows carries a provenance label (`Measured`).
- Tests: `node:test`, files in `packages/cli/test/*.test.mjs`. Fixtures are
  synthetic, generated by scripts, never copied from real transcripts.
- Read JSONL with `readJsonl()` from `src/ir/jsonl.mjs` (splits on `\n` only).
- Token estimates use `estimateTokens(text, kind)` / `estimateTokensFromBytes`
  from `src/ir/estimate.mjs`; `detectKind(text)` picks prose vs code.

Adapters build scopes with `requests` (usage only), `blocks` (with `firstRequest`,
and `lastRequest`/`droppedBy` only when the adapter knows it), `compactions`,
`handoff` (tokens + placeholder ratio), then call `finalizeRun(run, { instructionTokensEstimate })`
from `src/ir/finalize.mjs`, which runs reconciliation and fills `peak`, `summary`,
`coverage.estimatorError*`, `activeMs`, handoff ratios.

Request/block indexing rule: when the record carrying usage for request `i`
arrives, the content blocks it produced (assistant text, thinking, tool_use) get
`firstRequest = i + 1` (they are input to the next request). Blocks that arrive
between requests (user prompts, tool results, attachments, handoffs) get
`firstRequest = <index of the next request>`. Thinking blocks are never part of
occupancy but are kept for the ledger.

`turn` on a request = number of human prompts seen so far in that scope.

## Rules engine (`src/rules/`)

```js
// src/rules/<ID>.mjs, ID in S-01..S-12 and B-01..B-15
export default {
  id: "B-01",
  scope: "session" | "setup" | "subagent",
  severity: "high" | "medium" | "low",
  title: "Fat tool result",
  whyItMatters: "...",
  thresholdKeys: ["fatToolResultTokens"],
  evaluate(input, thresholds) => Finding[]
}
// input: { run?: Run, runs?: Run[] /* same repo, for recurrence */, setup?: SetupInventory, sessionStats?: SessionStats }
// src/rules/thresholds.json: { "fatToolResultTokens": 8000, ... } (every key documented with a one-line comment in thresholds.md)
// src/rules/index.mjs:
export async function loadRules() => Rule[]                       // readdir + dynamic import of [SB]-*.mjs
export async function evaluateRun(run, { thresholds, runs }) => Finding[]
export async function evaluateSetup(setup, { thresholds, runs, sessionStats }) => Finding[]
export async function loadThresholds({ home }) => Thresholds       // defaults merged with ~/.contextscope/thresholds.json
```

Finding `id` = `${ruleId}:${sha1(primaryEvidenceRef).slice(0, 10)}`; a finding
with empty `evidence` is a test failure. `fix.snippet` is platform-specific.

## Index (`src/index/`)

```js
export async function ensureIndex({ home, repoRoot, roots, onProgress }) => IndexState   // incremental by (size, mtimeMs, adapterVersion)
export async function readRun(runId) => Run | null
export async function listRuns({ projectKey?, vendor?, since? }) => OverviewRun[]
export async function buildOverview({ repoRoot, projectKey }) => Overview
export async function sessionStatsForRepo(projectKey) => SessionStats
export async function clearIndex({ home })
```
Index root: `~/.contextscope/index/v1/`. Manifest: `manifest.json` with
`{ files: { [absPath]: { vendor, size, mtimeMs, adapterVersion, runId, summary, projectKey, startedAt, findingsCount, findingsHigh } } }`.
Per-run file: `runs/<vendor>/<sha1(absPath)>.json` (the full Run + findings).
Absolute paths are allowed in the manifest only (it never leaves the machine);
API responses replace them with `~`-relative display paths.

## HTTP API (`src/contextscope.mjs`, token-guarded, loopback only)

- `GET /api/v1/overview` → `Overview`
- `GET /api/v1/runs/:vendor/:id` → `Run & { findings: Finding[] }`
- `GET /api/v1/setup` → `SetupInventory & { findings: Finding[] }`
- `GET /api/v1/findings?scope=&vendor=` → `{ findings: Finding[] }`
- `GET|PUT /api/v1/thresholds` → `Thresholds`
- `GET /api/v1/index/events` (SSE; `data: {"type":"progress","done":n,"total":m}` … `{"type":"done"}`)
- `POST /api/v1/index/refresh` → `{ ok: true }`
- `GET /api/v1/discovery` (kept for consent)
- Static UI from `packages/cli/ui/` at `/` (index.html, app.js, app.css). Token
  arrives as `?token=` on the first page load; the UI sends `Authorization: Bearer`.

## UI (`packages/ui/`)

Preact + signals + esbuild. `npm run build` writes `packages/cli/ui/`.
`npm run dev` serves fixtures from `packages/ui/dev/fixtures/` (see
`dev/server.mjs` header for the file mapping). Routes: `#/`, `#/session/:vendor/:id?scope=&request=`,
`#/setup`, `#/findings?scope=&vendor=`. Types are imported from `@ir/types.ts`.
Category colours and labels live in `src/categories.ts` (single source).
